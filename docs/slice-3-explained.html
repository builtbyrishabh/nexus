Slice 3 · PR #6 · full-channel ingest

The whole
catalog

Slices 0–2 could answer questions about videos we pointed at one by one. The product promise is a creator's entire channel. Slice 3 turns one command into a corpus: discover every upload, ingest them safely in parallel, and reach the videos that have no captions at all.

Discover

Every upload, no API key

youtubeLoader.discover() walks a channel's Videos tab to the end through Innertube continuations. A handle, a UC id, a URL, or any video all resolve to the owner channel.

Ingest at scale

Bounded, isolated, idempotent

ingestChannel() runs the per-video pipeline three at a time. One bad video fails alone; unchanged videos skip before any paid work; the CLI exit code tells CI the truth.

Whisper fallback

A way in for silent videos

When a video genuinely has no caption track, and only then, audio is transcribed through the Gateway. Off by default, capped at 25 MB, and never paid for twice.

Also riding in this diff: the Slice 2 fixes from PR #7 (the array-binding bug that broke every query, the context blurb on the query path, the Hormozi golden set). They were merged into this branch so it stays reviewable against main. Covered near the end.

Ground floor

Where Slice 2 left ingestion

Before this PR, ingestion was a single-video affair. pnpm ingest <videoId> ran one pipeline: fetch the caption track, chunk it with timestamps, write a Contextual-Retrieval blurb per chunk, embed, and upsert. It was already idempotent (a SHA-256 of the transcript decided whether anything was written), but three things stood in the way of "the whole channel":

  • No discovery. Nothing could list a channel's uploads. You had to know the video id.
  • A YouTube-flavoured orchestrator. The pipeline itself called toVideoId() and the loader returned transcript and metadata in one lump, so a re-run paid for the metadata request even when it was about to skip.
  • Captions or nothing. A video with captions disabled simply could not be ingested, and the identity regexes (what is a video id? a channel id?) lived in more than one place.

Slice 3 addresses all three, and it does so without touching the query path. Nothing in retrieve() or ask() changes for channel ingest; the corpus just gets bigger.

The map

How one command becomes a corpus

Hold this picture while reading the rest. Three phases: discover the channel once, decide per video whether there is any work to do, and write only when there is. The two dashed boxes are skip gates. They are ordered cheapest-first on purpose, so a re-run of an already-ingested channel costs almost nothing.

Two things to notice in the picture. First, metadata is fetched only in row 3. In Slice 2 the loader returned transcript and metadata together, so every re-run paid an oEmbed request before discovering it had nothing to do. Splitting the loader into loadTranscript() and loadMeta() is what makes the second gate cheap.

Second, the first gate never loads anything. A Whisper transcript is final: the audio will not change, and re-transcribing it is the most expensive thing ingest can do. So the pipeline checks the persisted provenance on the source row before touching the network at all. To force a re-transcribe, delete the row.

The wiring

Who imports whom

Seven files carry Slice 3. The shape to see is a layered tree with one pure leaf at the bottom: youtube-url.ts knows what a video id and a channel id look like and nothing else. Both the caption loader and the Whisper module depend on it; neither depends on the other. Before the review fixes, Whisper imported the loader for toVideoId while the loader imported Whisper for the fallback, an import cycle. Extracting the identity helpers into their own module is what broke it.

Read the arrows as a hierarchy of who is allowed to know what. The CLI knows about channels and single videos. channel.ts knows how to fan out. pipeline.ts knows the write recipe but takes its loader as an argument, so it never names YouTube inside ingestSource(). The loader knows YouTube. Whisper knows audio. The URL module knows regexes. A future book loader plugs in beside youtube-loader.ts and nothing above it changes.

Pillar 1 · Discover

Finding every upload without a key

The first version of this PR used YouTube's public RSS feed. It is the simplest thing that works, and it was rejected in review for one reason: the feed stops at the newest fifteen or so uploads. For a two-video test that is invisible. For a channel with hundreds of videos it silently delivers a sliver of the catalog while looking like success. The product contract says "entire catalog", so the loader now walks the channel's Videos tab through youtubei.js (Innertube, the same internal API the YouTube client uses) and follows continuation tokens until the tab runs out.

Any way of naming a channel works

resolveChannelId() accepts whatever a person is likely to paste and returns the canonical 24-character UC id. Cheap, local checks run first; only the ambiguous forms go to the network.

  • UCxxxxxxxxxxxxxxxxxxxxxxused as is, no request
  • …/channel/UC…id read out of the URL, no request
  • @AlexHormozi / AlexHormoziInnertube resolveURL → browseId
  • youtube.com/c/legacy-namesame resolver, handles legacy paths
  • youtu.be/o64cI6tebnUvideo → its owner via the video's own info
  • UCsomething-that-is-a-handlenot 24 chars, so treated as a handle

That last row is a real bug the review caught. An unanchored regex treated any string starting with UC as a channel id and built a dead /channel/ URL from a long handle. Now the id patterns are anchored and built from one string constant in youtube-url.ts, so the check cannot drift between callers.

One Innertube session is created lazily per process and shared. Innertube.create() is itself a network round trip for client config, so paying it once per channel rather than once per resolve matters at catalog scale.

The seam

SourceLoader grew up

The design contract (DESIGN.md §4a) has always said ingestion is source-agnostic: books are a new loader, not a rewrite. Slice 3 is the first time that seam was put under load, and it changed shape in two ways that are worth reading side by side.

Before · Slice 2

interface SourceLoader {
  discover(): AsyncIterable<SourceRef>;
  load(ref): Promise<LoadedSource>;
}
type LoadedSource = {
  source: SourceMeta;
  segments: Segment[];
};

// pipeline knew YouTube:
ingestVideo(input) {
  const id = toVideoId(input);
  // …load, hash, write
}

After · Slice 3

interface SourceLoader {
  discover(scope, opts?: { limit? })
    : AsyncIterable<SourceRef>;
  loadTranscript(ref): Promise<Transcript>;
  loadMeta(ref): Promise<SourceMeta>;
}
type Transcript = {
  segments: Segment[];
  provenance: "captions" | "whisper";
};

// pipeline knows nothing:
ingestSource(ref, loader) { // kind from ref }
ingestVideo(input) =
  ingestSource({ kind, externalId: toVideoId(input) }, youtubeLoader);
  • One call became two. loadTranscript() is the expensive call that drives the idempotency hash. loadMeta() is deferred until the pipeline has decided to write. This is the whole reason a no-op re-run is now free.
  • Provenance travels with the segments. A transcript says where it came from, and the pipeline persists that in source.metadata. That single field is what lets gate 1 skip a Whisper video without loading anything.
  • The orchestrator is generic. ingestSource(ref, loader) never names a source kind. ingestVideo() is a three-line wrapper that canonicalizes the input once and hands over the YouTube loader. A book loader gets the same treatment.

Everything else about the write is unchanged from Slice 2 and still matters: all remote work (transcript, contexts, embeddings) happens before any write, and the source hash plus the chunk swap commit in one transaction. A failed embed can never leave a fresh hash pointing at missing chunks, which the next run would then wrongly skip.

Pillar 2 · Ingest at scale

Many videos, one honest answer

ingestChannel() is short, and its shortness is the point: it collects the refs from discover(), then runs ingestSource() over them through the shared mapPool() helper with three videos in flight. Every design question it answers is about failure.

Takes in

A channel ref, an optional cap, and a callback the CLI uses to print each video as it finishes.

→
Gives back
ChannelIngestResult = { discovered, ingested, skipped,    failed, outcomes: VideoOutcome[] }

Counts plus one outcome per video, in discovery order regardless of which finished first.

Every video ends in exactly one of three states

ingested

New or changed transcript. Chunks were written; the title and chunk count come back.

skipped

Hash unchanged, or already Whisper-transcribed. Nothing written, nothing paid.

failed

Anything threw: no captions with the fallback off, a rate limit, a 25 MB audio file. The error message is kept.

Failure is isolated, not fatal. mapPool() itself fails fast: if the worker function throws, no new work starts. That is right for the contextualizer, where one doomed model call means the whole video is lost anyway. It would be wrong for a channel, where one caption-less video should not sink the other four hundred. So channel.ts catches per video inside the worker and turns the throw into a failed outcome, and the pool never sees an exception. The outcome is built once, in a single then(onOk, onErr), and reported once, so any future change to reporting has one home.

The exit code is the contract. A cron or CI step must not read a stale corpus as success. pnpm ingest --channel exits non-zero when any video failed or when nothing was indexed at all (a paused database, a bad key, an empty discovery). A run that quietly did nothing looks identical to a healthy one without this rule.

pnpm ingest --channel @AlexHormoziDiscover and ingest every upload. Exit 1 on any failure.
pnpm ingest --channel @AlexHormozi --limit 5Newest five only. Pays for five, not the catalog.
WHISPER_FALLBACK=true pnpm ingest --channel UC…Same, but caption-less videos are transcribed instead of failing.
pnpm ingest o64cI6tebnUSingle video, as before. Unchanged behaviour.

Pillar 3 · Whisper fallback

A way in for silent videos

Some videos have captions disabled. Without a transcript they cannot be in the corpus, and a creator's best talk is sometimes exactly the one with no captions. The fallback downloads the lowest-bitrate audio-only stream, sends it to a speech-to-text model through the AI Gateway (openai/whisper-1 by default, one env knob), and converts the result into the same Segment[] the caption path produces. From the pipeline's point of view the two sources are indistinguishable except for the provenance tag.

The interesting engineering is in when it is allowed to fire. The naive version, "captions failed, try Whisper", was rejected in review because a YouTube rate limit would fan out into a paid transcription for every video in the batch. The shipped rule is precise:

Three guards inside the rust path

  • Size, before and during download. Whisper rejects uploads over 25 MB. The declared contentLength is checked before a byte moves; for formats that do not declare one, the running byte count is checked while streaming and the stream is destroyed the moment it crosses the cap. The first version downloaded everything and then got a 413. At the lowest audio bitrate, 25 MB is roughly seventy minutes of speech, which covers most talks. Splitting longer audio with offset timestamps is a known next lever, not built.
  • Lowest bitrate on purpose. Speech-to-text gains nothing from high-quality audio, and it keeps far longer videos under the cap.
  • Never twice. Provenance is persisted, so gate 1 in the pipeline skips a Whisper video before loadTranscript() is even called. Re-running a channel with the flag on costs nothing for videos already transcribed.

Whisper segments carry start and end in seconds, so toSegments() is a straight mapping. The caption path is messier: the library reports offsets in milliseconds on one code path and seconds on another, with no flag. toSeconds() now combines two signals (median caption duration above 100, or a max offset beyond 24 hours of seconds) so a track whose durations are all zero no longer deep-links to ?t=1200000.

The load-bearing 20%

Decisions that ripple

Most of the diff is plumbing that conforms to a handful of decisions. These are the ones that would be expensive to reverse, in the order they matter, with what each one buys and what undoing it would cost.

DecisionWhy it is load-bearingIf reversed
discover
Innertube, not RSS		 RSS caps at ~15 uploads. "Entire catalog" is the product; a source that silently truncates fails the contract while reporting success. Large channels lose most of their history and nobody notices until a user asks about an old video.
seam
ingestSource(ref, loader) is source-agnostic		 The pipeline never names YouTube. Kind comes from the ref, the loader is injected. This is the seam the book loader will land on. Books become a second pipeline, and every fix to hashing or the transaction has to be made twice.
seam
loadTranscript() and loadMeta() are separate		 The hash is computed from the transcript alone, so a no-op re-run never pays for metadata. Catalog re-runs are cheap. Every nightly run makes one oEmbed request per video for no reason, and the "cheap re-run" story collapses at scale.
whisper
Provenance is persisted; Whisper is final		 A Whisper video skips before any load. The most expensive step in ingest can only ever be paid once per video. Re-runs re-download audio and re-pay STT for every caption-less video, every time.
whisper
Fallback only on genuine "no captions"		 Disabled, NotAvailable, or zero segments. Rate limits, unavailable videos and network errors propagate instead. A throttle cannot fan out into N paid transcriptions. One bad afternoon of YouTube rate limiting becomes a surprise bill and a corpus of transcripts that should have been free captions.
whisper
Off by default, 25 MB fail-fast		 The fallback pulls audio at ingest time. Nobody should pay for that without flipping a switch, and never after a full download. A first-time pnpm ingest --channel quietly downloads hours of audio.
identity
youtube-url.ts owns every id pattern		 One string constant per pattern, anchored, imported by loader and Whisper alike. This is what broke the import cycle and fixed the UC-handle bug. The video-id and channel-id regexes drift between callers again, and the loader/Whisper cycle comes back.
failure
Isolate per video in channel.ts; fail fast in mapPool		 The pool stays a generic primitive. The channel layer decides that one video's failure is survivable, and records it. Either the first caption-less video aborts a 400-video run, or the pool learns channel-specific rules it should not know.
contract
Non-zero exit if any failed or nothing indexed		 CI and cron read exit codes, not logs. A run that did nothing must not pass. A paused database or a bad key produces a green pipeline and a stale corpus.
hygiene
Dropped YOUTUBE_API_KEY		 No Data-API code path exists. Dead config invites a future contributor to build on a key nothing reads. Minor, but it would be the first lie in .env.example.

Riding along · PR #7

The Slice 2 fixes in this diff

On 2026-09-06 the first real corpus went in: two Alex Hormozi "Scale or Fail" episodes, 81 chunks. Running Slice 2 end to end on real data found three things. They were fixed on a separate branch (PR #7, merged to main) and merged into this branch so PR #6 stays reviewable. You will see them in the diff against main; they are not Slice 3 work.

  • Every query on main was broken. The Slice 2 hydrate query used ANY(${ids}::uuid[]). Drizzle expands a bare JavaScript array into a row value, not a Postgres array, so Postgres refused to cast a record to uuid[]. One helper, uuidArray(), now binds the array as a single parameter via sql.param. Both places that filter by id use it.
  • The context blurb now rides on the query path. Evidence.context carries the Contextual-Retrieval blurb; evidenceText() renders it as a "Context:" line in the packet the model reads, the judges grade against that same string, and the reranker scores context + "\n" + text, the exact string that was embedded. Measured without it: about a quarter of questions naming an entity only the blurb mentions were wrongly refused, and reranking promoted intro chunks. After: both modes pass the gate.
  • The golden set is now the Hormozi set. Seventeen answerable cases across both videos plus four refusal cases, including world-knowledge traps like "How did Alex start Gym Launch?" that the model knows but the corpus never says. pnpm eval --verbose prints each case's decision, scores, citations and answer.

The "context on the query path" change is a real shift in what the model reads, and it is not yet written into docs/DESIGN.md §4b. Worth locking in the next time that file is touched.

Still open

What this PR does not do

  • It has not been run against a real channel yet. End-to-end testing on 2026-09-06 was done on main (Slice 2) with two hand-picked videos. The first pnpm ingest --channel @AlexHormozi --limit N run is the next thing to do after merge, and the golden set should grow with the corpus.
  • Audio over 25 MB is skipped, not split. Chunking long audio into sub-25 MB pieces with offset timestamps is the known next lever for the Whisper path.
  • The caption unit heuristic is still a heuristic. One shape (a seconds-based track whose few cues each run over 100 s) cannot be disambiguated. The durable fix is to pin the caption format the library requests.
  • The hedged-refusal question is unresolved. Near-miss questions currently produce a refusal sentence followed by "the evidence does show…". The contract says an exact refusal. Strict refusal versus refuse-plus-nearest is a product call, still open.
  • The book loader is the real test of the seam. Until a second SourceLoader exists, source-agnosticism is a design claim, not a demonstrated one.

One command, the whole catalog, and nothing paid for twice.

Slice 3 in one line: discover every upload of a channel without an API key, ingest them three at a time through the same idempotent pipeline with per-video failure isolation, and reach caption-less videos through a flag-gated Whisper fallback that can only fire on a genuine "no captions" and only ever pays once.
