The Journey of a Message

You type one sentence. By the time the model reads it, it has been rewritten twice. On the way back it gets rewritten again before it's saved. This is every stop on that trip — with the real text at each stop.

📚

The whole thing in one picture

Think of Nexus as a librarian. You ask a question. The librarian doesn't answer from memory — they run to the shelves, grab 5 relevant quotes, staple them to your question, and hand that fat packet to a reader who can only answer using those quotes. The reader writes an answer with little footnote numbers. Then the librarian files a clean copy of just your question + the answer (no quotes) so tomorrow they remember the conversation. That's it. The rest of this page is just those steps, slowed down.

TURN 1

A fresh chat, first question

You type: What does Hormozi say about pricing?

STEP 1

The browser sends the bare minimum

chat-conversation.tsx

The chat box does not upload the whole conversation. It sends only your newest message and a threadId (which chat this is). Everything older lives on the server, so there's nothing to re-upload.

POST /api/chat — request body
{
  "message": {
    "id": "msg_a1",
    "role": "user",
    "parts": [{ "type": "text", "text": "What does Hormozi say about pricing?" }]
  },
  "threadId": "thread_xyz"
}
▼   server pulls out the plain text   +   looks up who you are
STEP 2

The route unpacks it & fetches past turns

api/chat/route.ts

Clerk confirms you're logged in (gives a userId). It squeezes the text out of the parts into a plain query string. Then it asks the store: "what was said earlier in this thread?" — this is the recall step. On turn 1 there's nothing yet, so history is empty.

what the route now holds
query    = "What does Hormozi say about pricing?"
userId   = "user_42"       // from Clerk, never trusted from the client
history  = []                // recallModelMessages(thread_xyz) → empty on turn 1

It hands all of that to the one function every surface funnels through: ask().

▼   now the interesting part   — the message gets FATTER
STEP 3

ask() runs to the shelves and staples quotes on

ask.ts → retrieve() → answer.ts

This is the librarian sprinting to the shelves. retrieve() searches the video transcripts for the 5 chunks most related to your question. Those become Evidence. Two things then happen to that evidence:

(a) It's turned into citations (title, timestamp, deep-link) and streamed back to your screen immediately — before the model has written a single word. That's why source cards can pop up first.

(b) It's numbered [1] [2] [3]… and glued in front of your question to make one big "user" message. This fat packet is what the model will read.

buildAnswerMessages() output — the single user message
// role: "user", content: ⌄
Evidence:

[1] How To Price Your Offer (at 3:42)
Charge more than you're comfortable with. The number that
makes you slightly nauseous is usually the right one...

[2] Value Equation (at 12:08)
Price is a signal. When you charge more, people assume the
thing is worth more, and they use it more...

… [3] [4] [5] …

Question: What does Hormozi say about pricing?
💡

Transformation #1: your 6-word question just became a ~500-word packet. You never see this. The model never sees your bare question alone — it always sees quotes-then-question. This is why the model can't make things up: the only facts in front of it are the quotes we chose.

▼   history (empty)  +  the fat packet   →   the model
STEP 4

What the model actually receives

nexusAgent.stream(turn)

The model gets a system prompt (its permanent rulebook) plus the turn. The rulebook says, in short: answer ONLY from the Evidence; if the quotes don't cover it, refuse; cite with [n]; never invent a number.

the full thing handed to the model
system:  You are Nexus. Answer ONLY from the provided Evidence.
         If it doesn't cover the exact question, refuse. Cite [n]…

user:    Evidence:
         [1] How To Price Your Offer … [2] Value Equation …
         Question: What does Hormozi say about pricing?

On turn 1 there's no prior conversation, so it's just system + this one user turn.

▼   model writes, streaming word by word
STEP 5

What the model gives back

textStream → route → your screen

Plain text with little footnote markers. The [1] and [2] point at evidence entry 1 and 2 — which are the exact same numbers as the citations we already streamed in step 3. That's how a footnote becomes a clickable link to the right video timestamp.

model output (streamed token by token)
Hormozi says to charge more than you're comfortable with — the
price that makes you slightly nauseous [1]. He also frames price
as a signal: charging more makes people value the thing more [2].
▼   answer finished streaming  —  now file a clean copy
STEP 6

persistTurn files a CLEAN copy

threads.ts · persistTurn()

Here's the twist most people miss. We do not save the fat packet. We save your plain question and the answer. The evidence quotes are thrown away from history (they were just scaffolding for this one turn). The citations ride along as a side-part so the [n] links still work after a page reload.

💡

Transformation #2 (the mirror image): going into the model the message got fatter (+evidence). Going into storage it gets thinner again (−evidence). Storage always holds the clean human conversation; the model always sees the evidence-stuffed version. Same turn, two different shapes.

TURN 2

A follow-up — where memory earns its keep

You type: What about the second one?

STEP 1–2

Same as before — but recall now returns something

route.ts · recallModelMessages

The browser again sends only "What about the second one?" + threadId. But this time recall pulls back the clean turn-1 pair from the store. Notice: it's the plain version — no evidence packet, just the human words.

history = recallModelMessages(thread_xyz)
[
  { role: "user",      content: "What does Hormozi say about pricing?" },
  { role: "assistant", content: "Hormozi says to charge more… [1] … signal [2]." }
]
▼   retrieval runs on the NEW question only  ·  history rides alongside
STEP 3–4

The key rule: history for understanding, evidence for facts

ask.ts

retrieve() searches on "What about the second one?" alone — it does not mix in the old question. Fresh evidence is fetched and stapled on, exactly like turn 1. Then history is placed in front of the new fat packet, so the model can figure out what "the second one" means.

what the model receives on turn 2
system:    …the rulebook…
user:      What does Hormozi say about pricing?      ← recalled
assistant: Hormozi says to charge more… [1] … [2].   ← recalled
user:      Evidence:
           [1] … fresh quotes for THIS question …
           Question: What about the second one?      ← new fat packet

So the model reads the history and understands "the second one" = the second idea from before (pricing as a signal), but it still answers only from the fresh evidence and cites this turn's numbers. History helps it understand; it never becomes a source.

🔒

The load-bearing boundary: history is context for wording, evidence is the only source for facts. That's why a follow-up can resolve "he / that / the second one" without the model ever being allowed to answer from something it merely remembers instead of something it can currently cite.

RECAP

The five shapes of one message

StopWhoWhat the message looks like there
1 · leave Browser Just your newest sentence + a thread id. Tiny JSON. No history uploaded.
2 · arrive Route Unwrapped to a plain query string; a userId attached; past turns fetched from the store as history.
3 · fatten ask() + Evidence. 5 quotes retrieved, numbered, glued in front of the question. Citations split off to the screen early.
4 · read Model Rulebook (system) + optional recalled turns + the fat evidence packet. Answers only from the quotes.
5 · return Model → you Plain text + [n] footnotes that line up with the citations from stop 3.
6 · file Store − Evidence. Only the clean question + answer (+ citations side-part) are saved — ready to be recalled next turn.
🎯

If you remember one thing

The message wears two outfits. For the model it wears the fat "evidence + question" outfit so it can answer without inventing. For memory it wears the thin "just the human words" outfit so tomorrow's conversation stays clean. ask() dresses it up; persistTurn() dresses it back down. That two-outfit trick is the entire design.
